# 0003. IDs and exact decimals

**Status:** Accepted, 14 November 2026

## Decision

- Every ID is a UUIDv7 generated by the application. IDs are time-ordered, so inserts stay index-local, and an audit event's partition follows from its ID (plan P4).
- Quantities and costs are PostgreSQL `numeric(20,6)`; prices allow at most 4 decimal places. Values cross the API as decimal strings (`"12.5"`) and all arithmetic happens in SQL, so no stock or money value passes through binary floating point (PRD 4.2).
- A variant's `quantity_scale` (0–6) limits the decimal places accepted for its quantities. Responses return the stored scale (`"10.000000"`).
- SKUs are unique per shop after normalization: trimmed, inner whitespace collapsed, upper case (PRD 4.1).

## Revisit when

A currency or unit needs more than 6 decimal places, or responses should be trimmed to the variant's scale for display.
